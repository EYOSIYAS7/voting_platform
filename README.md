# Voting Platform

A decentralized voting application built with Solidity, Hardhat, and Next.js. The smart contract can be deployed to **any Ethereum-compatible (EVM) chain** — Sepolia, Polygon, Ethereum Mainnet, Hyperledger Besu, or any other.

---

## Project Structure

```
Voting_platform/
├── contracts/          # Hardhat project — Solidity contracts, deploy scripts, tests
│   ├── contracts/
│   │   └── VotingPlatform.sol
│   ├── scripts/
│   │   └── deploy.js   # Deploys contract and syncs ABI to frontend automatically
│   ├── hardhat.config.js
│   └── .env            # Your private keys and RPC URLs (never commit this)
└── frontend/           # Next.js app — connects to the deployed contract via wagmi
    └── src/
        └── lib/
            └── abi/
                └── VotingPlatform.json  # Auto-generated by deploy.js
```

## Part 1 — Deploy the Smart Contract

### Step 1: Install Contract Dependencies

```bash
cd contracts
pnpm install
```

### Step 2: Configure Your Environment

Create a `.env` file inside the `contracts/` directory:

```bash
# contracts/.env

# Your deployer wallet's private key (without 0x prefix is also fine)
DEPLOYER_PRIVATE_KEY=0xYOUR_PRIVATE_KEY_HERE

# The RPC URL of the chain you want to deploy to
BESU_RPC_URL=https://your-chain-rpc-url.com

# The numeric Chain ID of your target network
BESU_CHAIN_ID=1337
```

> ⚠️ **Never commit your `.env` file.** It contains your private key. The `.gitignore` already excludes it.

**Common Chain IDs for reference:**

| Network               | Chain ID   | RPC URL Example                              |
|-----------------------|------------|----------------------------------------------|
| Ethereum Mainnet      | `1`        | `https://eth.llamarpc.com`                   |
| Sepolia Testnet       | `11155111` | `https://rpc.sepolia.org`                    |
| Polygon Mainnet       | `137`      | `https://polygon-rpc.com`                    |
| Arbitrum One          | `42161`    | `https://arb1.arbitrum.io/rpc`               |
| Hyperledger Besu      | `1337`     | Your Besu node RPC URL                       |
| Hardhat (local)       | `31337`    | `http://127.0.0.1:8545`                      |

### Step 3: Add Your Network to Hardhat (for non-Besu chains)

The `hardhat.config.js` has `hardhat` (local) and `besu` networks pre-configured.  
To deploy to **any other chain**, add a new entry to the `networks` block in [`contracts/hardhat.config.js`](file:///d:/Projects/Voting_platform/contracts/hardhat.config.js):

```js
networks: {
  hardhat: {},
  besu: {
    url: process.env.BESU_RPC_URL,
    accounts: process.env.DEPLOYER_PRIVATE_KEY ? [process.env.DEPLOYER_PRIVATE_KEY] : [],
    ...(process.env.BESU_CHAIN_ID ? { chainId: parseInt(process.env.BESU_CHAIN_ID) } : {}),
    timeout: 60000,
  },

  // ─── Add any EVM chain here ───────────────────────────────────────────────
  sepolia: {
    url: process.env.SEPOLIA_RPC_URL || "https://rpc.sepolia.org",
    accounts: process.env.DEPLOYER_PRIVATE_KEY ? [process.env.DEPLOYER_PRIVATE_KEY] : [],
    chainId: 11155111,
  },
  polygon: {
    url: process.env.POLYGON_RPC_URL || "https://polygon-rpc.com",
    accounts: process.env.DEPLOYER_PRIVATE_KEY ? [process.env.DEPLOYER_PRIVATE_KEY] : [],
    chainId: 137,
  },
  // ──────────────────────────────────────────────────────────────────────────
},
```

Then add the corresponding RPC URL variable to `contracts/.env`:
```bash
SEPOLIA_RPC_URL=https://rpc.sepolia.org
```

### Step 4: Deploy

Run one of the following commands depending on your target network:

```bash
# Deploy to the local Hardhat network (no real wallet or ETH needed)
pnpm deploy:local

# Deploy to the pre-configured Besu network
pnpm deploy:besu

# Deploy to any custom network you added (replace 'sepolia' with your network name)
pnpm hardhat run scripts/deploy.js --network sepolia
```

**What happens when you deploy:**

The [`deploy.js`](file:///d:/Projects/Voting_platform/contracts/scripts/deploy.js) script will:
1. Deploy `VotingPlatform.sol` to the target chain.
2. Print the deployed contract address to the console.
3. Save a full deployment record to `contracts/deployments/<network>.json`.
4. **Automatically copy the contract ABI and address** into the frontend:
   `frontend/src/lib/abi/VotingPlatform.json`

You will see output like:
```
Deploying VotingPlatform with account: 0xAbC...
✅ VotingPlatform deployed to: 0x1234...abcd
📄 Deployment info saved to: contracts/deployments/sepolia.json
📦 ABI + address copied to frontend/src/lib/abi/VotingPlatform.json
```

> **Copy the deployed address** — you'll need it for the next step.

## Part 2 — Connect the Frontend to the Deployed Contract

### Step 5: Configure the Frontend Environment

Navigate to the `frontend/` directory and create a `.env` file:

```bash
# frontend/.env

# The contract address printed by the deploy script
NEXT_PUBLIC_CONTRACT_ADDRESS=0xYourDeployedAddressHere

# Must match the chain you deployed to
NEXT_PUBLIC_BESU_CHAIN_ID=11155111
NEXT_PUBLIC_BESU_CHAIN_NAME="Sepolia Testnet"

# HTTP RPC URL — used to read data from the chain
NEXT_PUBLIC_BESU_RPC_URL=https://rpc.sepolia.org

# WebSocket RPC URL — used for real-time event subscriptions (optional)
NEXT_PUBLIC_BESU_WS_URL=wss://rpc.sepolia.org/ws
```

> **Note:** If you skip `NEXT_PUBLIC_CONTRACT_ADDRESS`, the frontend will automatically use the address that was written to `frontend/src/lib/abi/VotingPlatform.json` by the deploy script.

**How the frontend reads these values:**  
[`frontend/src/lib/config.ts`](file:///d:/Projects/Voting_platform/frontend/src/lib/config.ts) reads the env vars to configure the chain and contract address. [`frontend/src/app/providers.tsx`](file:///d:/Projects/Voting_platform/frontend/src/app/providers.tsx) passes this chain config to **RainbowKit** and **wagmi**, so the wallet connect modal and all contract calls automatically target the correct network.

## Part 3 — Run the Frontend Locally

### Step 6: Install Frontend Dependencies

```bash
cd frontend
pnpm install
```

### Step 7: Start the Dev Server

```bash
pnpm dev
```

Open [http://localhost:3000](http://localhost:3000) in your browser.

## Production Deployment (Docker + Kubernetes)

To deploy the frontend to a production cluster, use the provided scripts in the project root:

- **Linux/macOS:** `./deploy.sh`
- **Windows:** `./deploy.ps1`

These scripts build a Docker image, push it to GitHub Container Registry (GHCR), and apply Kubernetes manifests from the `k8s/` directory. You will be prompted for your GHCR username during the process.
